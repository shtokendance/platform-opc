# Loop 1：Deploy-OPC 后台左侧导航

## 问题

Deploy-OPC 管理后台当前使用顶部横向 Tab 切换应用、基础资源、Dockerfile 模板和存储卷模块。用户已确认改为固定左侧导航、右侧工作区的布局，并要求完成开发、推送 `release`，分别部署测试和正式环境。

## 目标

- R1 将现有四个顶部功能 Tab 改为清晰的左侧分组导航，右侧展示当前模块工作区。
- R2 保留现有浅色卡片式视觉风格，并明确当前菜单、悬停和窄屏状态。
- R3 将同步控制台、系统导航、刷新及模块新增操作放入合理的页面框架位置。
- R4 切换模块不刷新整个页面，并通过 URL hash 保留刷新后的当前模块。
- R5 完成自动化验证、独立代码审查、测试环境部署和正式环境部署，交付版本可追溯到 `release` 提交。

## 范围

- 仅调整 Deploy-OPC 管理后台 `/admin/deploy` 的菜单和页面框架，以及支持这些行为所必需的前端状态处理。
- 保留应用管理、基础资源、Dockerfile 模板、存储与卷四个模块及现有业务内容。
- 按已确认方向提供桌面左侧导航、窄屏收起能力和手机端抽屉导航。
- 推送交付提交到 `release`，使用项目部署 SOP 和指定 SSH skills 部署测试与正式环境。

## 非目标

- 不修改业务接口、数据模型、权限规则和既有业务操作流程。
- 不重新设计四个模块内的表格、表单、弹窗或抽屉。
- 不改造其他后台页面，不引入新的前端框架或构建体系。
- 不变更数据库拓扑、部署网络拓扑或生产凭据。

## 用户场景

- R6 管理员进入后台后，可从左侧直接进入任一模块，并明确识别当前位置。
- R7 管理员刷新页面或打开带 hash 的地址后，仍停留在对应模块。
- R8 管理员点击概览卡时，右侧工作区与左侧当前菜单同步切换。
- R9 管理员在窄屏或手机端仍能打开导航并操作全部四个模块，内容不被固定侧栏遮挡。
- R10 管理员在测试和正式环境获得一致的导航与既有业务功能。

## 约束

- 沿用仓库现有 Vue 3 单页和 Tailwind CSS 实现方式。
- 保留用户已有改动，交付只包含本 Loop 真实变更。
- 生产与测试部署均须保持主机密钥校验，复用服务器现有配置和凭据，不读取或输出秘密内容。
- 部署前记录运行版本，部署后核对新提交对应镜像、容器健康状态和页面行为，并保留回滚路径。

## 成功标准

- 四个功能模块均可通过左侧导航访问，当前项高亮，hash 同步和刷新恢复正确。
- 同步控制台、系统导航、刷新和各模块操作入口可用，既有模块功能不因框架调整失效。
- 桌面、窄屏和手机端不存在导航遮挡工作区或退化为顶部横向 Tab 的情况。
- 项目标准测试与构建通过，规格中的正常、失败、权限和边界路径均有验证结论。
- 独立 AI Review 达到 `READY_FOR_HUMAN_REVIEW`，提交者完成签署。
- `release` 包含交付提交；测试与正式环境运行该提交的镜像，健康检查和页面冒烟通过。
